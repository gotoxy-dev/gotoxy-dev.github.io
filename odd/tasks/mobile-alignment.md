# Feature: Mobile experience aligned with the desktop UI/UX

Objective: phones (≤ 767 px, checked at 390 px) get the same design language, motion and interactions as desktop, with touch equivalents for hover-only behaviour.
Branch: `feat/japon-journey-autoplay` (working tree only: the owner asked for no commits). Delivery: none until the owner asks. Test runner: none configured; checks are `npm run build` and a visual pass at 390 px (Chrome, 390 px iframe) plus 1536 px to confirm desktop is unchanged.

## Specs

- S1 Card → case view transition works on phones: the card media morphs into the case cover of the stacked layout (same framed browser window as the card), no leftover "ghost" of the card window over the page; the close direction (X, Escape, back) returns into the card. Desktop behaviour unchanged.
- S2 Navbar on phones: readable over any content (background/blur once the page scrolls), tap targets ≥ 44 px (MENU, language), menu closes with Escape, links not focusable while closed, booking link opens in a new tab like desktop, scroll lock that holds on iOS, anchors not hidden under the fixed bar.
- S3 Tap targets ≥ 44 px everywhere on phones: case close X, awards toggle, journey dots, back-to-top, footer links, language buttons.
- S4 Global fixes: `overflow-x` clipped on `html` too; the footer's phone "get in touch" size actually applies; smooth scrolling off under `prefers-reduced-motion`.
- S5 Case study on phones uses the desktop design language: cover in the framed browser window over the blurred ambient (as on desktop and the home card), the closing capture shown (framed), links styled like desktop (caps + ↗), entrance animations, spacing from tokens in px (no 3 px vw gaps), no extra empty height from the desktop snap markers, journey controls tappable.
- S6 Hero on phones: the particle G is fully visible and well placed (not cropped by the screen edge), and it can be turned and stirred with the finger (touch drag rotates; finger speed pushes particles like the mouse); the page still scrolls normally with vertical swipes. URL-bar show/hide does not reset the particles.
- S7 One phone tier and a coherent type hierarchy: phone rules at ≤ 767 px (480–767 no longer gets a mix of tablet and phone rules); hero headline stays the largest text; section titles do not shrink as the screen widens.
- S8 Hover-only interactions get touch equivalents (no hover styles stuck after a tap: hover styles only under `(hover: hover)`; tap feedback where useful; CTA arrow / small-link arrows visible on touch); Awards rows tappable as a whole; Insights shows all four services on phones and an image on tablets.
- S9 Project cards tuned for phones: cards visible as soon as they enter the screen (no empty lower half), scroll travel proportional to the media size, lighter browser-window chrome at small widths.
- S10 Desktop (≥ 992 px) looks and behaves as before; `prefers-reduced-motion` keeps everything visible without motion; `npm run build` passes.
